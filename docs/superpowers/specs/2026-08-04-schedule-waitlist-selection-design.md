# 일정별 대기자 신청 전환 설계

## 목표

워크숍 전체가 아니라 선택한 일정(분반) 단위로 신청 가능 여부를 표시한다. 정원이 마감된 일정은 결제를 시작하지 않고 해당 일정의 대기자 신청 폼으로 연결한다.

## 상태 규칙

| 일정 상태 | 일정 선택 목록 | 선택 가능 | 하단 버튼 | 동작 |
| --- | --- | --- | --- | --- |
| 정원 여유 | 날짜·시간 | 가능 | 신청하기 | 기존 결제 흐름 |
| 정원 마감 + 대기자 링크 있음 | 날짜·시간 + `정원 마감 - 대기자 신청` | 가능 | 대기자 신청 | Sanity의 `waitlistFormUrl`로 이동 |
| 정원 마감 + 대기자 링크 없음 | 날짜·시간 + `마감` | 불가 | 마감 | 결제·외부 이동 없음 |
| Sanity 수동 마감 | 날짜·시간 + `마감` | 불가 | 마감 | 기존 수동 마감 동작 유지 |

한 분반이 마감되어도 다른 분반의 신청 가능 여부에는 영향을 주지 않는다. 모든 분반이 마감되면 각 분반이 자신의 상태에 맞게 마감 또는 대기자 신청으로 표시된다.

## UI 동작

1. 일정 선택 목록은 정원 마감 일정도 표시한다.
2. 대기자 링크가 있는 마감 일정은 선택할 수 있다.
3. 대기자 일정 선택 후 일정 선택 버튼에는 선택한 일정이 유지되고, 하단 주요 버튼은 `대기자 신청` 링크로 바뀐다.
4. 대기자 링크가 없는 마감 일정과 수동 마감 일정은 선택할 수 없고 주요 버튼은 `마감`으로 표시한다.
5. 대기자 상태에서는 결제 RPC 및 NICEPAY 호출을 실행하지 않는다.

## 데이터 흐름

- 일정별 정원 및 현재 신청 수로 `isScheduleFull`을 계산한다.
- 워크숍의 `waitlistFormUrl`을 공통 대기자 링크로 사용한다.
- 일정별 상태 판정은 상세 화면의 선택 일정에 적용한다.
- 결제 등록·정원 차감·웹훅 처리는 기존 흐름을 변경하지 않는다.

## 예외 처리

- `waitlistFormUrl`이 비어 있거나 유효하지 않으면 마감 일정은 대기자 신청으로 노출하지 않는다.
- 대기자 신청 링크는 새 탭에서 열고 `noopener noreferrer`를 유지한다.
- 전체 워크숍 마감 판정은 결제 버튼 잠금에만 사용하고, 개별 일정의 대기자 전환을 가로막지 않도록 한다.

## 검증 기준

- 두 일정 중 한 일정만 정원 초과: 해당 일정만 대기자 신청, 다른 일정은 신청하기.
- 두 일정 모두 정원 초과: 두 일정 모두 대기자 신청.
- 마감 일정에 링크 없음: 마감 표시 및 선택 불가.
- 수동 마감: 기존 마감 표시 유지.
- 열린 일정: 기존 결제창과 일정별 정원 차감 흐름 유지.
- 대기자 일정 선택 후 결제 API가 호출되지 않고 폼 URL로 이동.
- 모바일·데스크톱에서 일정 선택 목록과 주요 버튼 레이아웃 유지.
